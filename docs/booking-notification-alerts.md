# Incoming booking alerts

Sound is on by default. The first permitted pointer/keyboard interaction silently unlocks browser audio; login/focus also attempts resume. If blocked, the Staff dashboard shows Enable Sound. New authenticated Online Pending rows trigger a prominent banner and a two-note chime, repeating no faster than every 15 seconds until acknowledged or no longer Pending. Five-second server-authorized polling remains unchanged; process changes stop alerts at the next successful poll. Acknowledgement is local to this browser origin, not a reservation status update.

Web Locks serialize sound decisions across same-origin tabs; localStorage persists only opaque reservation IDs and timestamps so outstanding alerts and acknowledgements survive refresh. No guest information or tokens are stored. Only currently authorized rows may appear in banners. Separate browsers/devices cannot share acknowledgements without a server change, which is outside this release. Unsupported Web Locks or inaccessible browser storage fail closed to avoid duplicate sounds; supported modern Safari/Chrome are required for cross-tab sound coordination. Background/suspended browsers and muted devices can delay or suppress audio; timers cannot guarantee an exact 15-second cadence under OS throttling. Keep the dashboard visible and device volume audible.

Manual acceptance: sign in, interact once, keep two same-origin dashboard tabs open, and during a separately approved synthetic test window submit one online Pending booking. Check one chime initially and after 15 seconds, a banner, then acknowledge in one tab and verify both stop. Refresh and verify no replay. Repeat with Confirm/Reject, blocked audio and mobile foreground/background. No real bookings are created by automated tests. No Supabase/booking settings change is required.
